## Android 适配

Android 已使用 OkHttp 的异步 WebSocket 读写和独立地图解码，原 50 ms 手动续发调度仍运行在主线程。主线程绘图、布局或其他短时工作会影响续发间隔，因此本轮将手动发送节拍移至专用后台发送器。无需复制 Windows 的双线程 socket 实现。

| 行为 | v0.8.0 实现 |
|---|---|
| 发送节拍 | `ManualSender` 按约 50 ms 节拍发送当前有效意图；界面只更新快照与刷新时间，不维护待重放运动队列 |
| 序号 | 发送器生成递增 `seq`，界面刷新次数不直接决定线上序号 |
| GUI 严重停顿 | 意图达到 250 ms 未刷新后撤销并锁住该次驾驶；界面恢复时清除旧意图，需用户重新点击“启用手动驾驶” |
| 停止与失活 | 手动停止、失焦、触摸取消、切页、退后台、日志导出和离散操作均先撤销后台意图；后续旧快照不能恢复旧驾驶 |
| 重连 | 新连接重新完成握手，旧连接快照和未确认命令不补发；重新启用仍受当前遥测、控制权和页面门控约束 |
| 模拟模式 | 模拟网关的输入、周期状态和延迟回复共享同步锁，避免后台发送与界面协程同时修改模拟状态；不连接硬件 |
| 发送积压 | 继续采用 v0.7.0 的立即断开策略，避免手动输入/停止或任务暂停/停止/取消继续排在旧帧后 |

手动方向正常松开仍只停止主驱动，滚刷和第五电推保持各自独立语义；触摸取消、显式停止或驾驶失活清除全部手动意图。第五电推许可撤销仍会清除其旧意图，许可恢复不会自动开启。

取消连接无法撤回已经发到操作系统或网络的字节，重连后仍需核对机器人任务状态。后台发送也不保证操作系统休眠、进程冻结或网络中断时继续运行，机器人端期限检查仍负责相应保护。

## 四种时间约束

| 约束 | 数值 | 用途 |
|---|---|---|
| Android 后台手动发送节拍 | 约 50 ms | 在意图和控制条件有效时续发最新输入；不是实测最坏时延保证 |
| GUI 意图快照有效期 | 250 ms | 限制后台使用未刷新输入的时间，到期锁住旧驾驶 |
| App 遥测门槛 | 800 ms | 限制机器人状态的可用年龄，仍计入网关排队及本地处理等待 |
| 网关手动输入看门狗 / 串口桥指令有效期 | 默认各 250 ms | 机器人端检查输入与指令期限，本轮未修改 |

GUI 意图期限与遥测期限是不同条件，两者都有效才允许续发。界面重新刷新不能把已过期遥测变成新鲜，也不能解除已锁住的旧驾驶。上述数值不是船体物理停稳时间。

## 现场验收

新版尚无 Android 真机及实船验收记录。现场需要记录手动持续输入时的实际发送间隔，并覆盖地图更新、日志导出、屏幕失焦、切页、锁屏/后台、Wi-Fi 中断和 Windows/Android 控制权交接。GUI 意图过期后恢复界面时，方向、滚刷和第五电推均不得自动恢复，需明确重新启用驾驶。

软件测试、Mock 和测试渲染只能验证相应软件路径。实船验收还需分别测量停止请求、机器人输出归零及船体惯性漂移，不将网关输入期限等同于整船停止时间。
