# v0.9.0 op-2 协议适配记录

日期：2026-11-11。Android 版本码 9；核对上游 `surface_robot/feature/op-2` 的固定提交 [`f33743cf9a53689a757a49400af19262f1dc2ba0`](https://github.com/YYYKblue/surface_robot/commit/f33743cf9a53689a757a49400af19262f1dc2ba0)。前一版 Android 基线为 `develop/8b8a46c`。

## 行为变化

| 项目 | v0.9.0 |
|---|---|
| 主驱动 | 整数 0～100%，滑条与 ±1 微调；25/50/75% 快捷选择 |
| 手动操作 | 无需申请或启用，直接按住方向键或开启辅助输出 |
| 旧网关 | 未声明 `continuous_drive_percent_v1` 时保留 25/50/75 三档；重连旧网关时不合法数值归一为 25 |
| 新网关未就绪 | 声明能力但字段缺失、格式错误或不可用时禁止手动输出，显示原因 |
| 控制恢复 | 旧动作全部清除；下一次明确操作自动先发一帧中性输入，至少隔一个 50 ms 节拍后再发送新意图 |
| 0% | 清除主方向；调高后需重新按方向，滚刷/第五电推保持独立 |
| 输出反馈 | 分开显示 App 请求与新鲜 F103 回报；RC 回报标为独立档位；过期状态不作为当前值 |

主驱动百分比表示 PWM 幅度，不是实测船速。v3 的 25/50/75% 分别是相对中位 100/200/300 μs，100%=400 μs；旧网关与物理遥控器的三档标度为 125/250/375 μs。手动调速不修改自动清洗参数。

## 协议和控制条件

WebSocket 协议仍为 `f1-operator-v1`，没有新增 App 显式 acquire/release 命令，租约由网关处理。连续输出能力通过 hello 协商；可用性取每次遥测 `drive_output`，严格要求整数 `min=0/max=100/step=1/firmware_protocol_version=3` 和布尔 `available=true`。不因旧 hello 曾经可用而忽略后续无效遥测。

除原有页面、前后台、控制端占用、任务忙碌、待确认操作和 800 ms 遥测门槛外，新能力还要求新鲜控制状态、已连接、Nano 控制源、READY/ACTIVE、已解锁且结果 OK。CTRL 和 ACK 累计年龄均小于 400 ms；累计字段原始年龄、网关 `stream.control_age_ms` 和 App 本地遥测年龄，后者已含 `server_queue_ms`。不比较不同机器的绝对时钟。

`connection_id/source/epoch` 改变即清除旧方向和辅助开关。新网关的 `manual_rearm_required` 只能由就绪会话内的中性 `manual_input` 解除，`manual_stop` 本身不解除。Android 在明确新操作时自动发送中性帧，避免仅打开手动页就占用其他操作端；由同一后台发送器保持先后顺序和序号，不同时连发两帧触发积压保护。

发送器继续独立运行约 50 ms 节拍，GUI 意图 250 ms 未更新即失效。遥测、定时器和旧回调不能自行重新启动；新输入从清空后的当前值更新单个字段，避免调速时带回旧方向或辅助开关。失焦、切页、后台、触摸取消、导出日志、断线和显式停止都保留停止语义。
